# Reflection

這次作業是製作一個骰子模擬器，功能包含產生 1 到 6 的隨機點數、統計擲骰子的次數、總和與平均值，並且根據骰子的點數改變文字顏色。我在完成這份作業的過程中有使用 AI 協助，但我沒有一開始就請 AI 直接產生完整程式，而是先自己依照題目建立 JFrame、JLabel、JButton，以及需要使用的變數，遇到不熟悉的語法或程式錯誤時再詢問 AI。

一開始在產生骰子點數時，我知道 Java 可以使用 `java.util.Random`，但是忘記實際的使用方法，因此詢問 AI。AI 告訴我可以先建立 `Random` 物件，再使用 `nextInt(6)`。我原本不清楚為什麼還需要 `+1`，後來理解到 `nextInt(6)` 產生的是 0 到 5，所以如果骰子需要 1 到 6，就必須寫成：

`random.nextInt(6) + 1`

這部分讓我重新理解 Random 的範圍，而不只是直接記住一行程式碼。

接下來我在處理「按下擲骰子按鈕後要執行程式」時，知道需要使用 `addActionListener()`，但是忘記完整的寫法。我一開始寫成：

`btn.addActionListener({ });`

後來透過 AI 才知道使用 Lambda 可以寫成：

`btn.addActionListener(e -> { });`

我也了解到 `{ }` 裡面的程式就是每次按下按鈕時會執行的內容，因此我把產生骰子點數、更新統計資料、改變文字顏色和更新 JLabel 的程式放在這裡。這讓我比較清楚 GUI 程式和一般由上到下執行的程式不同，按鈕的功能是等待事件發生後才執行。

在統計邏輯的部分，我一開始寫成：

`if (dice >= 6)`

然後把 `count`、`total` 和 `average` 的更新放在這個 if 裡面。後來 AI 提醒我，骰子的值只有 1 到 6，所以 `dice >= 6` 實際上只有骰到 6 的時候才會成立。這樣就會造成骰到 1、2、3、4、5 時完全不會統計，但是題目要求的是每擲一次都要統計。因此我把：

`count += 1;`
`total += dice;`
`average = ...;`

移到 if 判斷之外，讓每一次按下按鈕後都會更新統計資料。這個錯誤讓我發現，程式語法就算沒有錯，邏輯還是可能不符合題目的要求，所以執行結果也需要自己檢查。

計算平均值時，我原本直接使用：

`average = total / count;`

雖然 `average` 是 double，但 `total` 和 `count` 都是 int，所以 Java 會先進行整數除法。例如 7 / 2 得到的是 3，而不是 3.5，之後才把 3 存成 3.0。後來我把程式改成：

`average = (double) total / count;`

這樣 Java 就會使用浮點數除法，可以得到正確的小數結果。另外題目要求平均值顯示到小數點後兩位，因此我又使用 `String.format("%.2f", average)`，讓例如 6 顯示成 6.00。

在顯示統計資料時，我原本使用 `\n` 想讓 JLabel 換行，但是執行後發現 JLabel 不會像 Terminal 一樣直接處理換行。AI 建議我使用 HTML 的方式，例如：

`<html>...<br>...</html>`

其中 `<br>` 可以讓 JLabel 顯示多行文字。這是我以前不知道的 Swing 用法。

GUI 排版也是這次比較大的問題。一開始我直接寫：

`frm.add(lbl);`
`frm.add(btn);`
`frm.add(lbl2);`

執行後只看到最後加入的元件。我原本不知道原因，後來了解到 JFrame 預設使用 BorderLayout，如果沒有指定位置，元件都會被放到 CENTER，因此後加入的元件會蓋掉前面的元件。

曾經有建議使用 FlowLayout，使用之後三個元件確實都可以顯示，但是再回頭看題目後，我發現老師要求的是「上方顯示統計資料、中間顯示骰子點數、下方顯示按鈕」，所以 FlowLayout 雖然能讓程式顯示，卻不符合題目的版面需求。最後我改成：

`BorderLayout.NORTH`
`BorderLayout.CENTER`
`BorderLayout.SOUTH`

分別放置統計資料、骰子點數和按鈕。這讓我理解到「程式可以執行」不代表「程式符合題目要求」，還是需要自己判斷 AI 提供的方法是否適合。

另外，我也遇到過 `ClassNotFoundException`。一開始 AI 根據錯誤訊息推測可能是 package 名稱、class 名稱或檔案位置有問題，但是後來檢查 VS Code 的 Java 擴充套件日誌後，發現真正原因是 Java Language Server 的工作區快取異常，導致建置失敗，沒有產生需要的 class。最後使用 `Java: Clean Java Language Server Workspace` 清除工作區後，程式才可以正常執行。

這個問題讓我印象比較深刻，因為 AI 一開始的判斷並不是實際原因。這讓我知道 AI 的回答只能當成一種可能的方向，不能直接認為一定正確。錯誤發生時還是要觀察錯誤訊息、執行結果和開發環境的狀態，再判斷真正的原因。

這次完成作業後，我覺得 AI 最適合幫助我的地方是查詢忘記的 API、解釋語法、提供除錯方向，以及幫助我理解錯誤。但是如果直接把整個題目交給 AI 產生完整程式，我可能只會覺得程式看得懂，卻不知道為什麼要這樣設計。

這次我比較希望自己養成的方式是：先看題目、自己思考需要哪些變數和執行流程，能寫的部分先自己寫；如果只是忘記 API 或語法，再使用 AI 查詢；如果程式出錯，先理解錯誤發生在哪裡，再參考 AI 的建議修改。

我認為這樣使用 AI 比直接複製完整答案更有幫助，因為最後我不只是得到一個可以執行的骰子程式，也比較能理解 Random、ActionListener、資料統計、型別轉換以及 BorderLayout 各自在程式裡的作用。
